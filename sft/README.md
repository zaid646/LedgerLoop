# Supervised Fine-Tuning (SFT) — instruction tuning for LedgerLoop

A self-contained QLoRA pipeline that instruction-tunes **Qwen2.5-1.5B-Instruct** on a
mix of public instructions and LedgerLoop's expense-coding domain. It runs end-to-end
on a **free Google Colab T4 (16 GB)** — no rented GPU.

This complements `gpu/finetune_qlora.py` (a classification-style QLoRA job aimed at a
rented GPU). `sft/` uses HuggingFace `trl.SFTTrainer`, a public instruction corpus, and
measures instruction-following rather than only label accuracy.

## Results (checked in under `results/`)

Evaluated on **30 held-out LedgerLoop transactions** (unseen merchants) and **25 held-out
Dolly instructions**:

| Metric (`JSON key`) | Base Qwen2.5-1.5B | + LedgerLoop LoRA (seed 42) | Delta |
|---|---:|---:|---:|
| Held-out domain exact match (`domain_exact_match`) | 0.266667 | **0.866667** | +0.600000 |
| Domain token F1 (`domain_token_f1`) | 0.266667 | **0.866667** | +0.600000 |
| Format adherence (`format_adherence`) | 0.266667 | **0.866667** | +0.600000 |
| Domain completion loss (`loss_by_source.ledgerloop`) | 0.810746 | **0.060118** | −0.750628 |
| Dolly completion loss (`loss_by_source.dolly`) | 2.517077 | **1.544232** | −0.972845 |
| Overall completion loss (`completion_loss`) | 2.047040 | **1.722272** | −0.324768 |
| Overall perplexity (`perplexity`) | 7.744946 | **5.597230** | −2.147715 |

Rates are fractions (multiply by 100 for percent). `perplexity = exp(completion_loss)`;
the evaluator computes it with float32 `torch.exp`. Full-precision values are in
`results/eval_base.json` and `results/eval_adapter.json`.

### Why token F1 equals exact match

The F1 implementation has no EM fallback. It is standard multiset token F1 over
whitespace tokens, but both the normalized prediction and gold target are exactly one
of the 13 allowed category codes, each a single token (`PROFESSIONAL_SERVICES` contains
an underscore, not a space). A one-token prediction therefore scores either 1.0 when it
matches the one-token gold or 0.0 when it does not, so the mean token F1 is exactly
accuracy. This is constrained label generation, not free-form completion; Dolly is
evaluated by loss only.

Training run (seed 42): **63 optimizer steps**, **6m39s (398.85s)** on a free Colab T4,
average train loss **1.025**, last logged step loss **0.863**, SFTTrainer full-sequence
validation loss **0.717** (epoch 1: 0.751, epoch 2: 0.718, epoch 3: 0.717). Batch 2 ×
grad-accum 8 fit comfortably on the T4, so the batch-1/grad-accum-16 fallback was not
needed. The loss curve is `results/loss_curve.png`; the raw step log is
`results/trainer_log_history.json` and `results/loss_log.csv`.

### Multi-seed variance

The same recipe was run with seeds **42, 1 and 2**. Per-seed evaluator outputs and logs
are under `results/seeds/<seed>/`; `results/seeds/multiseed_summary.json` is generated by
`aggregate_seeds.py`.

| Seed | Exact match | Token F1 | Domain loss | Dolly loss | Overall PPL | Train loss | Runtime |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 42 | 86.7% | 86.7% | 0.060 | 1.544 | 5.597 | 1.025 | 6m39s |
| 1 | 90.0% | 90.0% | 0.057 | 1.546 | 5.592 | 1.007 | 6m44s |
| 2 | 90.0% | 90.0% | 0.066 | 1.541 | 5.612 | 1.010 | 6m34s |
| **Mean ± std** | **88.9% ± 1.9 pts** | **88.9% ± 1.9 pts** | 0.061 ± 0.004 | 1.544 ± 0.002 | 5.600 ± 0.011 | 1.014 ± 0.010 | 6m39s ± 5s |

Raw aggregate: `domain_exact_match = 0.888888888888889 ± 0.01924500897298752`;
`domain_token_f1` is identical for the reason above.

> Evaluation loss is higher than the Trainer's `eval_loss` because `evaluate_sft.py`
> masks the prompt and scores only completion tokens.

The base model leans heavily on `OTHER` for long-tail merchants. The adapter learns the
13-code taxonomy and the merchant/description mapping, while the lower Dolly loss shows
that general instruction-following did not collapse.

## Dataset

| Source | Train | Held out | Notes |
|---|---:|---:|---|
| LedgerLoop synthetic GL coding | 152 | 30 | 182 unique instruction-response pairs across 13 GL categories |
| Databricks Dolly 15k | 175 | 25 | 200 used from the 320-row checked-in sample; no-context examples |
| **Total** | **327** | **55** | |

- **Domain corpus**: generated deterministically by `domain_data.py` from the same GL
  taxonomy as `ai-service/app/schemas.py` (`TRAVEL`, `MEALS`, `OFFICE_SUPPLIES`,
  `SOFTWARE`, `HARDWARE`, `MARKETING`, `PROFESSIONAL_SERVICES`, `UTILITIES`, `RENT`,
  `INSURANCE`, `TRAINING`, `ENTERTAINMENT`, `OTHER`). Each merchant appears exactly once,
  so the held-out merchants are unseen by construction — this is a genuine
  merchant-generalization test, not a row-random leak.
- **Public corpus**: [Databricks Dolly 15k](https://huggingface.co/datasets/databricks/databricks-dolly-15k)
  (CC BY-SA 3.0). `data/public_dolly_sample.jsonl` is a checked-in 320-row sample;
  `format_dataset.py` uses the first 200 by default. If the file is absent, the script
  downloads the dataset and recreates it.
- **Formatting**: Qwen ChatML. Each record stores `prompt`, `completion` and the combined
  `text`. The training text ends with `<|im_end|>`:

```text
<|im_start|>system
You are LedgerLoop's expense-coding assistant. ...<|im_end|>
<|im_start|>user
Classify this business transaction ... Allowed categories: ...<|im_end|>
<|im_start|>assistant
MEALS<|im_end|>
```

Training uses the combined text with full-sequence language-model loss. The evaluator
uses the same prompt and masks it when computing completion loss.

## Hyperparameters

| Setting | Value |
|---|---|
| Base model | `Qwen/Qwen2.5-1.5B-Instruct` |
| Quantization | 4-bit NF4, double quantization, fp16 compute (QLoRA) |
| LoRA | r=16, alpha=32, dropout=0.05, no bias, all linear projections |
| Learning rate | 2e-4, cosine schedule, 3% warmup (2 steps) |
| Epochs / batch | 3 epochs; batch 2 × grad-accum 8 = effective batch 16 |
| Sequence length | 512, no packing |
| Optimizer | `paged_adamw_8bit`, max grad norm 0.3, weight decay 0.01 |
| Precision | 4-bit base + fp32 LoRA adapters (AMP scaler disabled; see caveats) |
| Seeds | 42 (headline), 1 and 2 for variance |
| Runtime | ~6–7 min per seed on a free T4; adapter saved to `outputs/.../seed-<seed>/final` |

## Run on a free Colab T4

1. Open <https://colab.research.google.com>, choose **Runtime → Change runtime type →
   T4 GPU**, and verify with `!nvidia-smi`.
2. Clone the repo and install the pinned environment:

```bash
git clone https://github.com/zaid646/ledgerloop.git
cd ledgerloop
git checkout feature/sft-instruction-tuning
pip install -q -r sft/requirements.txt
```

3. Build the data (uses the checked-in Dolly sample; downloads only if missing):

```bash
python sft/format_dataset.py
```

4. Fine-tune with QLoRA:

```bash
python sft/train_sft.py
```

5. Run the three checked-in seeds and evaluate each adapter:

```bash
python sft/evaluate_sft.py --output sft/results/seeds/base_eval.json
for seed in 42 1 2; do
  python sft/train_sft.py --seed "$seed" \
    --output-dir "sft/outputs/qwen2.5-1.5b-ledgerloop-lora/seed-$seed" \
    --results-dir "sft/results/seeds/$seed"
  python sft/evaluate_sft.py \
    --adapter "sft/outputs/qwen2.5-1.5b-ledgerloop-lora/seed-$seed/final" \
    --output "sft/results/seeds/$seed/eval_adapter.json"
done
python sft/aggregate_seeds.py
```

The adapter, tokenizer and `adapter_config.json` are written to
`sft/outputs/qwen2.5-1.5b-ledgerloop-lora/seed-<seed>/final/` (gitignored). Training
metrics, per-step logs, loss curves and evaluation JSON are written under
`sft/results/seeds/<seed>/`; the seed-42 headline files are copied to `sft/results/`.

### CPU / local smoke test

```bash
# Some Colab images preinstall torchao 0.10, which peft 0.21 rejects for
# non-quantized LoRA. Remove it for the CPU path only:
pip uninstall -y torchao

python sft/format_dataset.py --no-public
python sft/train_sft.py --model Qwen/Qwen2.5-0.5B-Instruct --no-4bit --device cpu --dry-run
python -m unittest discover -s sft/tests
```

`--dry-run` runs 10 steps with a 256-token limit. 4-bit is automatically disabled when
CUDA is unavailable. The CPU path was smoke-tested with the 0.5B model and one step
(train loss 3.515, `/tmp` output); the 1.5B T4 path is the supported full run.

## What this demonstrates

This is end-to-end **instruction fine-tuning (SFT)** with
`trl.SFTTrainer`, not a classification head. It covers **data preprocessing** (Qwen
ChatML prompt/completion formatting), **domain adaptation** to LedgerLoop GL-coding,
**evaluation** with completion loss, perplexity, token F1 and exact match, and
**reproducible free-T4 training** (pinned versions, checked-in data, per-seed logs and
metrics). A generic 1.5B instruct model scores 26.7% exact match on unseen
merchant/expense pairs; QLoRA on 152 in-domain examples raises seed 42 to 86.7% and the
three-seed mean to 88.9% ± 1.9 points, while Dolly completion loss falls 38.7%.

## Caveats and next steps

- The domain labels are synthetic and some are inherently ambiguous (e.g. "customer
  dinner and show" could be `MEALS` or `ENTERTAINMENT`). Strict exact match understates
  quality on those cases.
- The held-out domain set has only 30 examples, so one example is 3.3 points. The
  three-seed mean ± std is reported above, but this is still a small smoke-level
  estimate, not a benchmark.
- The general-instruction check is a 25-example loss measurement, not an accuracy
  benchmark.
- Mixed-precision autocast was disabled because Colab's PyTorch 2.11/CUDA 13 stack hit a
  `GradScaler`/bfloat16 incompatibility on T4. The base is still 4-bit NF4 and only LoRA
  adapters train, so this remains QLoRA.
- In the 0.5B pilot, completion-only loss underperformed (46.7% vs 63.3%), so
  full-sequence loss was retained; it was not re-tuned for 1.5B.
- Next: grow the domain set from human-reviewed corrections and the existing golden
  evals, hold out whole categories as well as merchants, compare 1.5B with 3B/7B and
  retrieval baselines, merge the adapter, and serve it through `gpu/serve_adapter.py`.
